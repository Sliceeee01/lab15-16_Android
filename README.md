# Student Planner — Студенческий планер

Приложение для отслеживания учебных дисциплин, расписания занятий и навигации между экранами.

## Реализованные экраны

- **Home** — список дисциплин
- **Details** — детальная информация о дисциплине
- **Profile** — профиль студента
- **Settings** — настройки приложения
- **Rospisanie** — расписание занятий на неделю
- **RospisanieDetail** — детали занятия

## Технологии

- Kotlin
- Jetpack Compose
- Navigation Compose

## Контрольные вопросы

**1. Что такое NavController и для чего он используется?**

NavController управляет навигацией — переходами между экранами и стеком назад. `rememberNavController()` сохраняет его при рекомпозиции.

**2. Как передать параметр в маршрут навигации?**

В маршруте пишем `"details/{subjectId}"`, при переходе — `navController.navigate("details/123")`. В экране достаём через `backStackEntry.arguments?.getString("subjectId")`. Обязательные параметры всегда нужны, опциональные — могут отсутствовать.

**3. Зачем использовать sealed class для маршрутов?**

Безопасность типов — компилятор проверит существование маршрута. Ошибка: написать `"detals"` вместо `"details"` — компилятор не поймёт, а sealed class подсветит.

**4. Что такое Back Stack и как им управлять?**

Стек экранов: `[Home] → [Home, Profile] → [Home, Profile, Settings]`. `popBackStack()` на Settings вернёт к Profile.

**5. Как работает startDestination в NavHost?**

Определяет первый экран при запуске. Можно изменить динамически через `navController.graph`.

**6. Что произойдёт при навигации на несуществующий маршрут?**

Приложение упадёт с ошибкой `IllegalArgumentException`. Нужно проверять маршруты или обрабатывать ошибки.

**7. Зачем нужен параметр launchSingleTop в навигации?**

Предотвращает создание дубликатов экрана в стеке. Без него: Home → Home → Home. С ним: останется один Home.
